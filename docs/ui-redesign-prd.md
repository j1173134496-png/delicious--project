## 1. 目标与边界

把现有小程序改成统一的「暖色手账」视觉：八条首页更有陪伴感，菜谱和相册的主要操作更明显，表单文字与操作不再被裁切。四个 Tab 的名称和顺序保持「八条 → 菜谱 → 相册 → 我的」；13 个原有页面都保留。7 张新稿是视觉依据，样例数据与未说明的交互不作为新增业务要求。

| 本轮做 | 本轮不做 |
|---|---|
| 还原 6 个有稿页面，其中新增/编辑菜品共用一路由；使用公共组件统一 7 个无稿页面 | 新 IP 替换、四形态与贴纸状态重新绘制、3D 或新动画引擎 |
| 调整布局、样式、状态反馈、称谓一致性，修正重复导航、裁字和遮挡 | 修改养成/菜谱/绑定业务规则，迁移或重置已有数据，修改 Storage schema、AppID 或基础库 |
| 补齐现有功能的正常、空、忙碌、失效和错误呈现 | 云环境、真实登录、跨设备绑定/共享、真实 AI、远程反馈、主动推送 |

**本地能力说明：** 聊天是本地模拟回复；绑定只改变本机状态；相册和菜谱的「上传」在本轮实际保存到本机；反馈保存后仍未发送。原型的「共同记录」不能被实现成云端功能或文案承诺。未绑定仍可保存本机照片。

**参考和取舍：** [新 UI 原型](new/) 用于视觉，[现状截图交接](ui-handoff/八条与你-现有界面与重设计交接.md) 用于对照，[旧 PRD](../PRD-情侣小程序「八条与你」.md) 用于了解产品背景。发生冲突时，本轮行为以当前代码和评审确认的边界为准，不从旧 PRD 恢复未交付的能力，也不把图中日期、数字、占位词或系统控件画样当成实现指令。

## 3. 交互与页面要求

### 01 · 八条：房间、养成和聊天

- 上半屏呈现猫咪场景、名称/等级、饱食度、心情值、今日喂养和经验。下半屏呈现消息列表、输入和发送。数值、进度填充和滑块位置绑定已有状态；`0/100` 不能画成满格。两页统一用「心情值」指同一指标，不新增「快乐值」字段。
- 保留「喂八条」、抚摸按钮及点击/长按猫咪。一手势只记一次，保留每日 3 次喂养上限、养成和升级规则。首页与个人页显示同一状态。首轮继续用现有四形态 PNG，不以房间稿中的白猫为由直接换主角；缺状态图沿用现有同形态素材及 Emoji 降级。
- 保留本地欢迎消息、双方消息气泡、时间及输入发送。补已有消息、空输入、发送失败、初始化异常/重试和喂养达限的呈现。键盘弹出时，输入框、发送及当前对话仍可操作；不要为了塞进一屏而缩小文字。

### 02 · 菜谱图鉴：分类、卡片和新增

- 保留未解锁、已解锁、甜品区及现有筛选口径；甜品区不是第三种解锁状态。计数来自现有数据，`9 / 0 / 3` 只是初始示例。已选分类不能只用颜色标识。
- 使用手账双列卡片表现封面、菜名和状态。未解锁卡统一写「待解锁」或「添加照片解锁」，不用稿里的「待定占位」；带图卡显示真实图片，失效时用统一占位。保留缺内容时的引导。
- 卡片进详情；「新增菜品」进 06。悬浮按钮不得盖住卡片的关键信息或底部 Tab，列表最后一张可完整滚到可操作区域。

### 03 · 我们的相册：情侣信息、签名和照片

- 关系卡显示头像、邀请/在一起天数、照片数、签名及编辑。未绑定不显示虚假的已相伴天数，可邀请，也可直接存本机照片；绑定后显示现有纪念日计算结果。签名编辑保留保存/取消、长文和失败状态。
- 空相册使用一个「上传第一张照片」主按钮；有数据时按年月分组并保留上传入口。保留大图切换、关闭、图片失效占位、可用时的长按保存和本人删除及确认。空态插画不出现在有照片的列表内。

### 04 · 我的：资料、关系和成长

- 保留编辑资料、生成/输入邀请码、分享、设置与隐私、关于的现有去向。头像、昵称、签名、性别、生日、纪念日和关系都是真实本机值。长昵称、签名及日期允许合理换行或截断，不挤掉编辑按钮。
- 成长区保留等级、当前状态、经验、累计喂养、聊天次数、心情、饱食、今日喂养及下一形态条件。累计次数不照搬原型的 `0/`；目标进度才用「当前 / 目标」。最高等级不继续显示不存在的下一形态。
- 升级阈值不变：Lv.1→Lv.2 喂养 30 次且聊天 50 次；Lv.2→Lv.3 喂养 100 次且解锁 10 道菜；Lv.3→Lv.4 纪念日达到 365 天。合法旧等级不降级。

### 06 · 新增/编辑菜品：同一组件，两种入口

- 新增用空菜名，编辑预填已有数据；同一表单组件，不新增路由。保留现有分类、评分、评价/备注与照片。菜名必填，最多 30 字；备注最多 300 字。可无图先保存菜品；补图后按原规则解锁。
- 评分用 5 颗心，0 分不显示任何一颗为已选。选中状态和 `当前评分 n/5` 必须一致；不因原型五颗粉心而改变评分默认值或可编辑规则。详情页未解锁的点赞/评分限制继续保留。
- 显示 `n/9`、真实缩略图及图片失效状态；添加照片用独立图标和短标签，不把长字塞进窄方格。验证空菜名、未选图保存、已到上限、取消选图、保存中、保存失败和重试；不重复提交，不将部分失败报成成功。

### 07 · 上传照片：先选图、再记回忆

- 保留相册/拍照选择，至少一张、单批最多 9 张；选图后显示可辨认的缩略图和计数。默认日期来自设备，允许今天或过去；保留描述与逗号分隔标签，现有字段规则不变。表单底部清楚标注本机保存。
- 验证空提交、选 1 张、选到上限、取消、权限不可用、图片失效、日期非法、存储/文件失败和成功返回相册。选图和保存期间要有可读反馈；保存失败留在页面供用户处理。

### C 批 · 无单独新稿页

这些页面不默认另起视觉方向。从 02/06 试做确定的卡片、标题、表单、说明文字与按钮延展，保留现有功能和入口。以下状态纳入验收：

| ID | 保留与补齐 |
|---|---|
| 05 | 未解锁可补图，已解锁展示照片并可评分/点赞；保留编辑、删除确认；找不到菜品时有返回入口。减少重复的补图说明。 |
| 08 | 原头像/换头像、昵称、性别、生日、纪念日、个性签名、保存；覆盖默认值、长输入、选图不可用、日期错误、保存失败。 |
| 09 | 分开「我的邀请码」和「输入 Ta 的邀请码」；保留生成、复制、分享和确认。深链只预填、不自动绑定；覆盖格式错误、自绑、已绑定、解绑确认及能力不可用。说明为本机模拟。 |

| 11 | 保留产品介绍、四个模块、本机模式、版本能力边界和反馈入口；长文可滚动。 |

| 13 | 保留分类、5–500 字反馈、可选联系方式、记录与复制；覆盖表单校验、无记录、有记录和保存失败；只标「本地保存，尚未发送」。 |

## 4. 公共样式与素材实现

- **视觉语言：** 奶油纸色作背景，深棕用于正文和描边，珊瑚色用于主操作，暖黄用于标签/引导，淡紫用于陪伴/次操作。胶带、纸纹、虚线和装饰贴纸用于强调，不压过正文。A 批首版确定色值、字号、间距、描边与圆角，再共享给 B/C，避免每页各抄一套。
- **公共组件：** 手账卡片、分段选择、主/次/危险按钮、表单行、照片网格、标签、空与错状态、头像和占位。原生 `button`、`input`、`textarea`、`picker` 保留真实交互、焦点和可读名称；评分和开关不用单靠色彩表示。主要按钮要有默认、按下、禁用和忙碌样式。
- **导航与适配：** 保留系统状态栏、微信胶囊、系统返回和现有路由；每个页面只呈现一组标题/返回入口，Tab 只出现在主页面。优先沿用原生导航和 Tab，再换图标、颜色；不将原型中的手机边框、状态栏和假胶囊绘进页面。小屏优先滚动，不按 JPG 高度硬定布局；检查键盘、最后一行和底部安全区。
- **保真策略：** 整页 JPG 仅作参考。布局、颜色、边框、文字和动态内容用原生组件和 WXSS；房间、相册空态插画、Tab 图标等需要位图的部分单独交付。优先请 UI 提供可导出素材（房间无猫/无字、空态插画、正常/选中图标），没有时先用轻量背景、已有资源或可替换占位，不裁整页冒充可用素材。首轮使用旧 IP 时，涉及新白猫的装饰也用旧角色或中性装饰，不混入新 IP。
- **包体门槛：** 2026-11-18 运行资源审计，`miniprogram/` 源文件统计为 `1,639,685 B`，仓库预算 `2,097,152 B`，余 `457,467 B`。这不是上传后的微信实测包大小。每批跑资源审计，记录新增资源大小；若逼近预算，优先减装饰、压缩独立素材，不删除四形态或把必需图片改为联网依赖。`docs/new/` 原图及贴纸不纳入运行包。
