# 八条与你 v1.4 第一版交付与试用部署

更新时间：2026-10-15（Asia/Shanghai）

## 当前可以交付的内容

这一版是离线优先的微信小程序 MVP，导入项目后可以直接体验四个 Tab：八条、菜谱、相册和我的。聊天回复使用本地 mock，猫咪成长、绑定、菜谱、照片元数据和反馈写入当前设备；图片文件由小程序本地文件系统管理。

这一版没有接入微信登录、跨设备绑定、云数据库、云存储、远程反馈、真实 LLM 或主动推送。服务器地址不能直接改变这些行为，必须先接身份、数据和文件服务。

## 第一版试用方式

1. 解压 `releases/batiao-love-v1.4.0-20261015.zip`。
2. 用微信开发者工具导入解压后的目录，使用其中的 `project.config.json`。
3. `project.config.json` 是 AppID 的唯一来源；README 中的游客模式说明是历史兼容文案，导入时以开发者工具显示的账号和 AppID 为准。
4. 先在模拟器检查四个 Tab，再用真机测试输入、滚动、长按、选图、保存和返回/重进页面。
5. 试用期间记录机型、基础库、页面路径、操作步骤、Console 错误和截图；不要把本机数据当作云端数据。

## 服务器选择

### 推荐：微信云开发 CloudBase

如果目标是让情侣双方跨设备共享绑定、聊天、相册和菜谱，优先开通与小程序绑定的 CloudBase 环境，而不是先买一台裸 VPS。CloudBase 直接提供小程序端 SDK、文档数据库、云存储、云函数和微信身份能力，适合把当前 Service 层逐步替换成远端实现。

第一阶段只需要：

- 一个开发环境；
- 微信身份登录；
- `users`、`couples`、`cats`、`messages`、`photos`、`recipes`、`feedback` 集合；
- 云存储图片目录；
- 绑定、聊天、相册和反馈四组云函数或受控数据库规则；
- 开发环境的备份和最小权限规则。

当前代码已经把业务访问集中在 `miniprogram/services/`，接 CloudBase 时优先替换这些 Service，不直接在页面里散落云调用。

### 什么时候才买传统服务器

只有在需要自建 Node/Go API、代理真实 LLM、运行管理后台或接第三方系统时，才需要 VPS/CVM/云托管。那时还要准备 HTTPS 域名、微信小程序合法域名、日志、备份、密钥管理和数据删除策略。没有这些配套，单独买服务器不会让当前小程序获得跨设备同步。
